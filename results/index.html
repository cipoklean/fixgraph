The Cypher that produced it

MATCH (s:Signature {id: $sig})<-[:HIT]-(e:Episode)-[:IN]->(f:Facet) RETURN e.id AS eid, e.ts AS ts, e.seq AS seq, f.key AS fkey
MATCH (s:Signature {id: $sig})<-[:HIT]-(e:Episode)-[:TRIED_OK]->(x:Fix) RETURN e.id AS eid, x.id AS fid, x.action AS action, x.kind AS kind, x.title AS title
MATCH (s:Signature {id: $sig})<-[:HIT]-(e:Episode)-[:TRIED_FAIL]->(x:Fix) RETURN e.id AS eid, x.id AS fid, x.action AS action, x.kind AS kind, x.title AS title

These are the exact statements the adapter runs — the narrow self-hosted dialect: integer ids, UNWIND batch upserts, directed single-type relationship patterns, anchored MATCH only.

Honest limits

The synthetic tier uses hand-designed hidden rules — it bounds, not proves, real-world performance. Where a vector arm matches the graph on a slice, the tables say so. REQUIRES chains are inferred from observed order and only ever reorder candidates. Facet vocabulary is coarse: patch-level differences are invisible. See README for the real Docker tier.

Go-to-market

Buyer: engineering teams running many coding-agent sessions and CI jobs where the same environment failure is rediscovered every session. Wedge: one-minute MCP install + CLI wrapper — useful from the second occurrence of any failure. Compounds: every session adds outcome data that cannot be rebuilt from documentation. Expansion: opt-in shared graph for open-source toolchains. Pricing (proposal): per-seat SaaS; self-hosted node free. Why HydraDB: the lookup is a multi-hop environment-conditioned traversal, and the episode log only grows — object-storage-backed history is the fit.
